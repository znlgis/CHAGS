# 三十六计 · 第五辑（并战计 25–30）方案

> 依据：[三十六计方案.md](三十六计方案.md)。本辑交付 **第 25–30 计、6 个游戏**，
> **不新增模板** —— 六计全部是给已有模板加一个模式（总方案第五节的计划）。
>
> 这是"复用模板"路线的最大一次考验：**六个模板各加一个新模式，老模式一律不许碰**。

## 〇、硬约束

1. 判定放 `<模板>.logic.ts`（不许 import Phaser），场景只喂墙钟；autoplay 走真实操作同一条路。
2. **零惩罚**：被清点发现、敲错东西、试探期露馅、对手掉下来 —— 都只是重来或代价。
3. **老模式逐行不许改**：`swap.shell` / `probe.knock·spot` / `stillness.bide` / `siege.vital·support·close` /
   `show.draw` / `chain.pass` 的判定与既有单测**一个字都不许改**（第四次实践，做法同前）。
4. 引文口径不变：战例原文未确证的，用《三十六计》本计按语（`source.book = 《三十六计·并战计》`）。
5. 适龄化：不出现流血死亡；第 27 计的"装糊涂"是忍，不是骗人；第 30 计的"接管"是接手岗位，不是夺权。

## 一、六个新模式

### 1. `swap.beam` 偷梁换柱（25）

**机制**：一排**承重柱**要换成新柱，外形要一模一样。与 shell 的差别在于：换一根要**按住干一会儿**
（`workMs`），而检查者每隔 `checkMs` **清点**一次 —— 清点时正拆着的那根会被发现（那根的进度清零，
记一次 seen，零惩罚）。

| 字段 | 说明 |
|---|---|
| `posts[]` / `spares[]` | `{id,x,y,radius,kind}`：柱子与新柱（kind 要对得上） |
| `workMs` | 换一根要按住多久 |
| `checkMs` | 每隔多久清点一次 |

判定：`beamStart(level)`、`startWork(state,postId,t)`、`tickWork(level,state,t,dtMs,holding)`、
`isPostRebuilt`、`check(level,state,t)`（清点打断未完成的）、`isBeamDone`。

### 2. `probe.hint` 指桑骂槐（26）

**机制**：不能点名。场上几样东西（桑树 / 槐树 / 钟 / 鼓），还有一个"该听懂的人"——
敲**对**那样东西（`listener.wants` 那个 kind），他会自己往前一步；敲别的只是没收获。
走够 `steps` 步，他自己做出正确的选择。

| 字段 | 说明 |
|---|---|
| `props[]` | `{id,x,y,radius,kind}`：可以敲的东西 |
| `listener` | `{x,y,radius,wants}`：该听懂的人，以及他听得懂的那个 kind |
| `steps` | 要他走几步 |

判定：`hintStart()`、`knockHint(level,state,propId)`、`hintProgress`、`wrongKnocks`、`isHintDone`。
**refine**：至少一个 prop 的 kind 等于 `listener.wants`。

### 3. `stillness.feign` 假痴不癫（27）

**机制**：对手一次次**试探**（假动作）。试探期间**任何点击都算露馅**（记一笔 slip，零惩罚）；
试探之间的**空档**里才能行动（点 `action` 推进一步）。推进 `steps` 步，机会就成熟了。

| 字段 | 说明 |
|---|---|
| `tests[]` | `{id, testMs, gapMs}`：每次试探多久、之后的空档多久 |
| `action` | `{x,y,radius}` |
| `steps` | 要在空档里行动几次 |

判定：`feignStart()`、`feignPhaseAt(level,t)` → `{testId, phase:'test'|'gap'|'done'}`、
`tapActionFeign(level,state,t)`（test 期点 = slip+1，gap 期点 = progress+1）、`isFeignDone`。

### 4. `siege.ladder` 上屋抽梯（28）

**机制**：先给方便 —— 按顺序把阶梯一级级搭好（点一下搭一级），对手顺着往上走；
等他走到位，再把梯子抽掉（点梯子）。

| 字段 | 说明 |
|---|---|
| `rungs[]` | `{id,x,y,radius}`：阶梯（按顺序搭） |
| `bait` | `{x,y,radius}`：他要去的地方 |
| `ladder` | `{x,y,radius}`：抽梯的地方 |
| `climbMs` | 他沿梯往上走多久 |

判定：`ladderStart(level)`、`buildRung(level,state,rungId)`（只认下一级）、`allRungsBuilt`、
`ladderPhase(level,state,t)` → `'building' | 'climbing' | 'ready' | 'done'`、
`pullLadder(level,state,t)`（只在 ready 之后生效；早了 = 他掉回来，进度清零，零惩罚）、`isLadderDone`。

### 5. `show.borrow` 树上开花（29）

**机制**：借现成的东西（树、城墙）把小队显得很大。手里有几面旗，要**分配到支点**上；
每个支点能挂的旗数有限（`capacity`），每面旗在它上面顶多少"规模"由支点决定（`weight`）。
挂出来的规模 ≥ `needed` 就算成 —— 可以随时撤下来重挂。

| 字段 | 说明 |
|---|---|
| `props[]` | `{id,x,y,radius,capacity,weight}` |
| `flags` | 手里一共几面旗 |
| `needed` | 规模到多少算成 |

判定：`borrowStart()`、`assignFlag(level,state,propId)`、`unassignFlag(level,state,propId)`、
`flagsLeft(level,state)`、`scaleAt(level,state)`、`isBorrowDone`。
**refine**：Σ capacity ≥ flags；把旗都挂到最好的支点上时 Σ weight×flags ≥ needed（有解）。

### 6. `chain.step` 反客为主（30）

**机制**：每一步都要**先被允许**。点 `grant` 求允许 —— 允许只持续 `grantMs`；
在有效期内点下一个岗位才能接管，过期就作废（要重新求，零惩罚）。接管完全部岗位 = 成了主导。

| 字段 | 说明 |
|---|---|
| `posts[]` | `{id,x,y,radius,label}`：要接管的岗位（按顺序） |
| `grant` | `{x,y,radius}`：求允许的地方 |
| `grantMs` | 允许持续多久 |

判定：`stepStart()`、`askGrant(state,t)`、`grantLeftMs(state,t)`、`isGranted(state,t)`、
`takeOver(level,state,postId,t)`（只认下一个 + 允许有效）、`takenPosts`、`isStepDone`。
**refine**：`grantMs` 必须够点完一个岗位（`grantMs ≥ 600`）—— 数据写太短会变成手速游戏。

### 顺手抓到一个跨全站的点击竞态（`baseScene.tapToContinue`）

全量 e2e 里"故事必须听完"挂了一次，复跑 3 次挂 1 次 —— 不是计时假失败：听完第二幕后点一下
**进不了玩法**。真因是连点保护的起点写错了：点击区**从建区时刻**起锁 350ms，而"这一幕念完"
（`story:ready`）与点击区建好是同一瞬间，孩子在听到念完那一刻抬手就点，正好落在锁里；此时护盾
已经销毁，于是既不翻页也不提示（点了什么反应都没有）。现在锁从**上一次真的翻页**起算
（`packages/phaser-kit/src/tapGuard.ts`：三行纯规则 + 单测），连点保护原样保留。修完复跑 5 次全过。

**教训**：这条规矩值得单测。它不是"Phaser 场景里的时序细节"，而是一条能写成三行纯函数的判定；
写成纯函数之后"锁的起点写错"一眼可见 —— e2e 只能**碰运气**撞到它（1/3 的概率，正好撞上了）。
