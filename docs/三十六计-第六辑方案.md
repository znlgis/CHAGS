## 一、四个新模式

### 1. `lure.favor` 美人计（31）

**机制**：先看清楚**他最在意什么**，再送出对的那一样。他平时目光就落在**那样东西**上
（`glanceAt` 周期性回到它），孩子得先看出来；送对了 `needOffers` 次就打动了他，送错了只是白送
（东西回到手里，零惩罚）。

| 字段 | 说明 |
|---|---|
| `gifts[]` | `{id,x,y,radius,kind,speak}`：手里的几样东西（kind 各自不同） |
| `target` | `{x,y,radius,wants}`：他，以及他在意的那样（kind） |
| `needOffers` | 送对几次才算打动（默认 1） |
| `refuseLine` | 送错时那句话（双语可译） |

判定：`favorStart()`、`offerFavor(level,state,giftId)` → `'loved'|'refused'`、
`favorsGiven(state)`、`isFavorDone(level,state)`、`glanceMs`/`glanceAt(level,t)`（他此刻在看哪一样）。
**refine**：`wants` 必须命中某一样 gift 的 kind；每样 gift 的 kind 不能重复。

### 2. `stillness.calm` 空城计（32）

**机制**：**该不动的时候一下都不能动**。开局只有一个动作 —— 大开城门（点 `gate`）；
之后他盯着看 `watchMs`、移开目光 `gapMs`，交替 `watches` 轮。
盯着的时候点任何地方都算“动了”：这一轮白忍（记一笔 slip，零惩罚），只能等下一轮；
**忍住 `needed` 轮**（期间一下都没点）他就退了。

| 字段 | 说明 |
|---|---|
| `gate` | `{x,y,radius}`：大开城门（开局唯一动作） |
| `watches[]` | `{id,watchMs,gapMs}`：他看多久、移开多久 |
| `needed` | 要忍住几轮（≤ watches.length） |
| `doubtLine` / `leaveLine` | 起疑时 / 他退走时那句话 |

判定：`calmStart()`、`openGate(level,state)`、`calmPhaseAt(level,state,t)` →
`{watchId,index,phase:'gate'|'watch'|'gap'|'done'}`、`tapCalm(level,state,t)`、
`cleanWatches(state)`、`isCalmDone(level,state)`。
**refine**：`needed ≤ watches.length`；每轮 `watchMs ≥ 1200`（太短就不算“忍住”）。

### 3. `twoline.plant` 反间计（33）

**机制**：让来访的人**自己看到**你想让他看到的东西。他来回踱步、时不时瞟一眼案上；
点 `redirect`（弄出点动静）他就转头看别处 `lookAwayMs` —— **趁这个空档按住 `spot`** 把东西摆上去。
摆到一半他回过头（空档结束）= 被你手忙脚乱的样子露了馅：进度清零、记一笔 caught，零惩罚。

| 字段 | 说明 |
|---|---|
| `visitor` | `{from:{x,y},to:{x,y},walkMs,radius}`：他来回一趟多久 |
| `spot` | `{x,y,radius,plantMs}`：按住多久摆好 |
| `redirect` | `{x,y,radius,lookAwayMs}`：点一下让他转头多久 |
| `caughtLine` / `plantedLine` | 露馅时 / 摆好之后他看见时那句话 |

判定：`plantStart()`、`redirectLook(level,state,t)`、`lookAwayLeftMs(state,t)`、
`plantHold(level,state,t,dtMs,holding)` → `'planting'|'exposed'|'idle'`、
`plantProgress(state)`、`isPlantDone(level,state)`。
**refine**：`plantMs ≤ lookAwayMs`（一个空档里必须摆得完，否则这一关不可能过）；
`lookAwayMs ≥ 900`。

### 4. `chain.domino` 连环计（35）

**机制**：环环相扣 —— 先点 `ignite` 起头，然后**按顺序**点上 `links`；
每一环点亮后，下一环必须在 `windowMs` 之内点上，**断了就从头再来**（零惩罚，记一笔 break）。
前一步为后一步铺路：顺序点错和不点一样，只是没反应。

| 字段 | 说明 |
|---|---|
| `ignite` | `{x,y,radius}`：起头的地方 |
| `links[]` | `{id,x,y,radius}`：按顺序点过去的几环（3–5） |
| `windowMs` | 一环点亮后下一环的时限 |
| `breakLine` | 断了时那句话 |

判定：`dominoStart()`、`igniteChain(level,state,t)`、`dominoPhaseAt(level,state,t)` →
`{index,remainingMs,running}`、`advanceDomino(level,state,linkId,t)` →
`'ok'|'wrong'|'expired'|'notStarted'`、`isDominoDone(level,state)`。
**refine**：`windowMs ≥ 900`（低于这个数就变成比手速了）。

### 分派方式（这一次是五分支并行）

31/32/33/35 各一个分支（每个模式一个），34+36 合成一个"纯复用"分支。两件事值得留档：

1. `packages/templates/src/index.ts` 是五个分支都要碰的共享文件 —— 由 Lead **先留四行占位注释**，
   每个分支只替换自己那一行：并行改一个文件，零冲突。
2. 四个新模式的 schema 与 refine 在开工前就由 Lead 冻结，分支只按字段名写判定，
   于是"数据不可能有解"这类问题全部在构建期被拦住（例如 `plantMs > lookAwayMs`、
   `windowMs < 900`、`needed > watches.length`）。
