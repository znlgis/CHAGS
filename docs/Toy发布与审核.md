# 上 B站 Toy（哔哩哔哩玩具）的发布与审核自查

> 依据：[《Toy 开发者 FAQ》](https://www.bilibili.com/opus/1241171666570051585)（更新至 2026.10.23）与
> [Toy 发布页 FAQ](https://www.bilibili.com/toy/publish/guide/faq)。平台规则会变，**以发布页最新公告为准**。
> 本文只记录本项目（`apps/site/dist`）与这些条款的对应关系，以及每次发版要跑的那条命令。

## 0. 一条命令

```bash
pnpm dist:toy    # 构建站点 → 跑平台硬性门禁 → release/chags-toy-v<版本>.zip
```

产物结构（**zip 根目录**，不再套一层 `dist/`）：

```
index.html
assets/…
```

`scripts/pack-toy.mjs` 会把 FAQ 里能本地验证的硬性条款当成门禁跑一遍，任何一条不过就**不出包**：

| 门禁 | 对应条款 | 本项目现状（2026-11 实测） |
|---|---|---|
| zip 根目录有 `index.html` | 七·5 构建产物要放在 ZIP 根目录 | ✓ |
| `index.html` ≤ 1 MB | 一·15 入口文件 1 MB 上限 | ✓ 0.7 KB |
| 整包 ≤ 50 MB | 一·6 文件包 50 MB，更大需单独申请 | ✓ 672 KB（解压后 1.9 MB） |
| 只用白名单后缀 | 七·1 非白名单文件会被自动过滤 | ✓ 只有 `.html` `.css` `.js` |
| 无 sourcemap | 体积与源码暴露 | ✓ 构建没有开 map |
| 无站外 `src`/`href`/`fetch` 绝对地址 | 四·4、四·12 不得跳转站外 | ✓ 全部相对路径 |

## 2. 发布时要手动选对的两个选项

这两条**代码管不了**，只能在上传页选，但选错会直接毁掉目标用户：

### 2.1 类型不要选「游戏」

> FAQ 一·13：类型设置为「游戏」后，**未成年人将自动无法游玩**。

本项目面向的是小朋友（家长页、20 分钟休息提醒、适龄设计都在），选「游戏」等于把核心用户挡在外面。
发布时选 **工具 / 科普 / 互动玩法** 一类（以发布页当下提供的分类为准），并在简介里写清「面向 6–10 岁儿童的典故小游戏」。

### 2.2 标题与文案已经中性化（本仓库的现行口径）

机审先看卡面标题、封面与文案正文，所以八个计名里带字面敏感词的已经换成同义的中性四字名。
**内部 id 与玩法一律没动**（`stratagem.number` 决定大厅里的「第 n 计」），只换展示名与读音：

| # | 原计名 | 现行标题 | 拼音 | 英文标题 |
|---|---|---|---|---|
| 3 | 借刀杀人 | 借力成事 | Jiè lì chéng shì | A Borrowed Sword |
| 5 | 趁火打劫 | 趁势取利 | Chèn shì qǔ lì | Seize the Moment |
| 10 | 笑里藏刀 | 笑里辨心 | Xiào lǐ biàn xīn | A Smile That Reads the Heart |
| 12 | 顺手牵羊 | 顺手得助 | Shùn shǒu dé zhù | Lead the Sheep Along |
| 14 | 借尸还魂 | 借名归心 | Jiè míng guī xīn | A Borrowed Name |
| 18 | 擒贼擒王 | 擒王定局 | Qín wáng dìng jú | Catch the Ringleader |
| 22 | 关门捉贼 | 关门落锁 | Guān mén luò suǒ | Lock Every Exit |
| 25 | 偷梁换柱 | 偷换关键 | Tōu huàn guān jiàn | Swap the Key Piece |

两条口径的分界：

- **面向孩子的文案**（卡面标题、故事旁白、题干、选项、揭晓语）**不出现**杀 / 死 / 血 / 尸 / 毒 / 贼 / 劫 / 偷；
  能用中性说法就用中性说法（例如「才免于一死」→「才避开危险」、「没有杀伤的蒿箭」→「不会伤人的蒿箭」）。
- **《三十六计》原典引文**（`source.quote`、「庖丁解牛」里的刀、司马迁与《庄子》的原文）**逐字保留**：
  那是要教的内容本体，删改就成了伪造出处。出处页只摆引文与书名，不做二次演绎。

改文案时别只改一处：卡面标题在 `packages/content/src/entries/<id>.json` 的 `title`/`pinyin`、
游戏包的 `games/<id>/src/manifest.ts`、英文补丁 `packages/content/src/i18n/en/<id>.json` 各有一份，
`apps/site/src/registry.test.ts` 会拿 manifest 与内容条目对账，`content:check` 会拦标题重复。

## 2.3 发布页还要填的

建议的对外命名：`历史典故游戏 · 一个典故一个小游戏`，封面用「曹冲称象」这类正向画面 ——
封面与图标是审核重点，别直接拿「借力成事」这种计策名当主视觉。

## 3. 已知的体验差异（不属于审核项，但要知道）

| 现象 | 原因 | 处理 |
|---|---|---|
| 在 B站 App 内没有旁白声音 | Android WebView 没有实现 Web Speech API，`speak()` 会走 `unavailable`；故事文字仍然在画面上 | 文字是主要通道，已保证不依赖语音；后续可换真人配音（`AudioBus` 只需换实现） |
| 存档换设备就没了 | 用的是 IndexedDB / localStorage，Toy 建议改用云存档（FAQ 三·11） | 现有降级路径不会报错；要接 `Toy SDK` 的云存档是下一步 |
| 横屏 / 沉浸模式下的安全区 | Toy 的顶栏与胶囊会压住角上的按钮 | `#app` 已用 `env(safe-area-inset-*)` 让开刘海；进入 Toy 后建议在真机上过一遍右上角按钮 |

## 4. 每次发版前的清单

1. `pnpm verify` 全绿（类型 / lint / 单测 / 内容体检 / 构建 / 体积）；
2. `pnpm dist:toy` 出包，门禁六项全 ✓；
3. 在发布页选**非「游戏」**类型，填好封面、图标、简介、分类标签；
4. 先用「链接访问」发一版，在 App 真机上点一遍：大厅 → 玩一局 → 退出 → 家长页长按；
5. 确认无误后再转「所有人可见」。
