## 一、两个新模板 + 三个扩展

### 1. `swap` 替换（21 金蝉脱壳 · shell）

**机制**：一排"还站在那儿的人"（`posts`）+ 一堆替身（`spares`）。把替身放到位置上（**样子要对**）；
检查者每隔 `peekMs` 抬头看一次 —— 没换好的位置会被看见，**那个位置就被戳穿、要重新换**（零惩罚）。
全部换好之后，自己从 `exit` 走掉。

| 字段 | 说明 |
|---|---|
| `mode` | 本辑只有 `'shell'`（第 25 计偷梁换柱以后再加 `beam`） |
| `posts[]` | `{id, x, y, radius, kind}`：要换的位置（4–6 个） |
| `spares[]` | `{id, x, y, radius, kind}`：可用的替身 |
| `peekMs` | 检查者每隔多久看一次 |
| `exit` | `{x, y, radius}` |

判定：`swapStart()`、`placeSpare(state, postId, spareId)`（样子不对 → 原样返回，只提示）、
`isPostSwapped`、`swapCount`、`peek(state, t)`（到点检查：没换的位置撤销换装、记一次 seen）、
`leave(state, t)`、`isShellDone(state)`（全换好 + 已离开）。
**refine**：posts 与 spares 的 `kind` 必须一一配得上（每个 post 都有一个同 kind 的 spare）。

### 2. `chain` 连环（24 假道伐虢 · pass）

**机制**：先谈成"借路"（`envoy`），再**按顺序**取下沿途关口（`gates`），最后回师（`home`）。
顺序不能跳：没借到路，一个关口也拿不了；前一个关口没拿下，后一个动不了。

| 字段 | 说明 |
|---|---|
| `mode` | 本辑只有 `'pass'`（反客为主 / 连环计以后再加 `step` / `domino`） |
| `envoy` | `{x, y, radius}` 谈借路的地方 |
| `gates[]` | `{id, x, y, radius, label}`，按顺序（3–5 个） |
| `home` | `{x, y, radius}` 回师 |

判定：`chainStart()`、`askPass(state)`、`hasPass`、`takeGate(state, gateId)`（不是下一个 → 原样返回）、
`nextGate(level, state)`、`takenCount`、`returnHome(state)`、`isPassDone(state)`。

### 3. `siege` 扩展：`support`（19 釜底抽薪）与 `close`（22 关门捉贼）

- **support**：火堆底下几根柴，点一根抽走一根，火势下降；`base: true` 的那根是**根上的柴**，
  抽掉它火势骤降。火势到 0 = 成。
  `{ mode:'support', fire:{x,y,level}, logs:[{id,x,y,radius,relief,base}], hint }`
  refine：至少一根 `base`；所有 `relief` 之和 ≥ `level`。
- **close**：贼会从某个出口跑（`escapeAfterMs` 之后），玩家要在那之前把每个出口关上（各自 `closeMs`）。
  `{ mode:'close', exits:[{id,x,y,radius,closeMs}], thief:{x,y,radius}, escapeAfterMs, hint }`
  refine：`ΣcloseMs < escapeAfterMs`（否则不可能全关上）；**贼跑掉只是重来**（零惩罚）。

### 4. `window` 扩展：`stir`（20 混水摸鱼）

与 `fire`/`glimpse` 不同：**窗口是自己搅出来的**。点水面搅浑（`murk` 涨），浑水期鱼才慢下来；
不搅就一直清、一直抓不到。浑浊随时间澄清。

新增字段：`stir: { x, y, radius, perTapMs, clearPerSec, muddyAt }`；
新增判定：`murkAt(state, t)`、`stirAt(state, t)`、`isMuddy(state, t)`；
`tapAt` 在 `stir` 下只在浑浊时接受（清了就抓不动，零惩罚）。
refine：`mode === 'stir'` ⇒ `stir` 必填；`fire`/`glimpse` ⇒ 不许写 `stir`。

### 5. `matchup` 扩展：`order`（23 远交近攻）

一圈势力（`neighbors`）：**近的先解决、远的先结好**。按正确顺序点过去；点错只提示，可以重排。

新增字段：`neighbors: [{id, x, y, radius, label, stance: 'attack'|'ally'}]` + `sequence: string[]`（正确顺序）；
新增判定：`expectedNext(level, state)`、`pick(state, id)`、`pickedCount`、`wrongPicks`、`isOrderDone`。
refine：`sequence` 覆盖所有 neighbor id；至少一个 attack、一个 ally。

**两处计划上的失误，记在这里备查**：

1. **我漏排了一个游戏**：任务分派时把 `chain` 模板和"金蝉脱壳"分给了同一个分支，
   却忘了第 24 计假道伐虢也要用 `chain` —— 三个分支都交付后才发现 `jiadao-faguo` 没人做，
   临时补了第四个分支。教训：**分派任务要按"交付物清单"逐个勾销**，
   而不是按"模板 + 一个代表游戏"分。
2. **英译套名不统一**：子代理各自把《混战计》译成 Melee / Confusion 两种，
   而 i18n 里的 `stratagem.set.4` 是 Confusion —— 集成时统一成了 Confusion。
   教训：**跨分支的共享词汇（套名、模板名、事件名）应该写进任务书**，让分支照抄而不是自创。
