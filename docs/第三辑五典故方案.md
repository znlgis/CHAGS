## 0. 先说最大的风险：五则都在春秋战国，最容易做成同一件事

十二部现有的主线动词是：**称**（等量代换）、**补**（形状配对）、**射**（瞄准）、**填**（连点）、**追**（长按）、**挖**（连点 + 交接）、**撑 / 化**（连点 + 拖光球）、**尝 / 疏 / 等 / 点 / 解**（第二辑）。

这一辑五则全落在春秋战国（前 575 – 前 239），题材又都是"讲道理"的寓言；如果偷懒都用"拖到对的地方"，做出来就是第七次换皮。方案给每一则一个**只属于它的动词**，再给每一则一张签名画面：

| 典故 | 动词 | 手感 | 签名画面（记忆锚点） |
|---|---|---|---|
| 刻舟求剑 | **刻** | 在船帮上刻一道痕；船一漂，刻痕就跟着走了 | 船靠了岸，船身一道刻痕，剑还在上游的水底 |
| 狡兔三窟 | **凿** | 在草地上凿窟；狐狸堵住一个，还有别的 | 三个洞口成品字形，兔子从最远的那个探出头 |
| 百步穿杨 | **练** | 自己一步一步往后退，柳叶一片比一片小 | 一箭穿过百步外的柳叶，箭尾还在抖 |
| 朝三暮四 | **分** | 在一条绳上把橡子左右拨，猴子时怒时喜 | 七颗橡子串在一条绳上，拨成四颗，猴子就笑了 |
| 庖丁解牛 | **游** | 刀在骨缝里游；硬砍就"当"一声 | 一张完整的骨架摊在灯下，一把十九年如新的刀 |

**刻 / 凿 / 练 / 分 / 游** —— 没有一个和现有十二部重样。

唯一需要正面处理的重叠是**刻**：曹冲称象里也有一"刻"（刻水痕）。但那里刻的是水位，是等量代换的一个步骤；刻舟求剑刻的是参照系，而且**刻错了地方**。两部的画面（船 + 大象 + 大秤 vs 江 + 剑 + 记号）、判定、结局完全不同 —— 验收第 5 条专门查这个。

## 2. 模板策略：3 个新模板 + 1 次扩展 + 1 个专属场景

沿用已经验证过的做法：**模板只留"循环与判定"，画面全部外置**。

| 模板 | 用途 | 复用前景 |
|---|---|---|
| **`mark`（新）** 在会动的世界上做记号 | 刻舟求剑 | 荆人涉澭、郑人买履、守株待兔等"老办法失灵"类 |
| **`burrow`（新）** 预留退路 + 威胁封堵 | 狡兔三窟 | 曲突徙薪、未雨绸缪、居安思危等"提前准备"类 |
| **`split`（新）** 总量不变的两份分配 + 观众反应 | 朝三暮四 | 不患寡而患不均、二桃杀三士等"分配与感受"类 |
| `aim`（**扩展**）加一个可选的"距离阶梯" | 百步穿杨 | 纪昌学射、惊弓之鸟（后羿的数据一个字段都不用改） |
| 专属场景 `butcher` | 庖丁解牛 | 一次性机制，留在游戏包里（沿用盘古 `chaos`、烽火 `beacon` 的做法，schema 照旧登记在模板层） |

### 2.1 `mark` —— 记号刻在哪儿，差别就在哪儿

```ts
export const MarkSurfaceSchema = z.object({
  id: z.string().min(1),
  kind: z.string().min(1),          // 怎么画由游戏决定：boat / tree / rock / buoy
  x: z.number(), y: z.number(),
  radius: z.number().positive(),
  /** 这个面会不会跟着船走：船帮 = true，岸上的树 / 水面的浮标 = false */
  drifts: z.boolean(),
  /** 刻下去时的一句旁白（双语可译） */
  speak: z.string().min(1),
});

export const MarkLevelSchema = z.object({
  /** 剑落水的地方：从头到尾不动，而且一直在画面里 */
  sword: z.object({ x: z.number(), y: z.number(), radius: z.number().positive() }),
  surfaces: z.array(MarkSurfaceSchema).min(2).max(4),
  driftMs: z.number().positive(),        // 船从落剑处漂到岸边要多久（autoplay 自动缩短）
  driftDistance: z.number().positive(),  // 漂多远 —— 记号的误差就是它
  hint: z.string().min(1).max(24),
})
.refine((l) => l.surfaces.some((s) => s.drifts) && l.surfaces.some((s) => !s.drifts), {
  message: '至少要有一个"会漂走"的面和一个"不动"的面，否则这一关没有可比较的选择',
  path: ['surfaces'],
});
```

- 判定只有两条纯函数：`surfaceWorldX(surface, boatX)`（记号此刻在世界里的位置：会漂的加偏移，不会漂的不动）、`reachSword(surface, boatX, sword)`（从记号处下水，够不够得着剑，按 `sword.radius` 容差）。
- 单测：刻在船帮 → 漂走后误差 = `driftDistance`；刻在树上 → 误差恒为 0；船还没漂就下水 → 也能捞到；两个面各刻一道 → 各自独立判定；退化关卡（`driftDistance` 为 0）被 schema 挡住；autoplay 路径不卡死。

### 2.2 `burrow` —— 退路要几条，是被危险的数量逼出来的

```ts
export const BurrowSpotSchema = z.object({
  id: z.string().min(1),
  x: z.number(), y: z.number(), radius: z.number().positive(),
  kind: z.string().min(1),      // 怎么画由游戏决定：草丛 / 土坡 / 石头下
});

export const BurrowWaveSchema = z.object({
  id: z.string().min(1),
  /** 这一次危险会同时守住几个洞口 —— "三窟"就是被这个数字逼出来的 */
  blocks: z.number().int().min(1),
  speak: z.string().min(1),     // 危险来的时候的一句话（双语可译）
});

export const BurrowLevelSchema = z.object({
  spots: z.array(BurrowSpotSchema).min(2).max(4),
  digsNeeded: z.number().int().positive(),   // 每个洞要挖几下才算通
  waves: z.array(BurrowWaveSchema).min(1).max(3),
  hint: z.string().min(1).max(24),
})
.refine((l) => Math.max(...l.waves.map((w) => w.blocks)) < l.spots.length, {
  message: '有危险一次堵住的洞口数不少于洞口总数 —— 这一局无论怎么挖都躲不过去',
  path: ['waves'],
});
```

- 判定：`openBurrows(dug, spots)` / `escapeRoute(dugCount, blocks)` —— **已挖通的洞 > 被封堵的洞**，兔子就有路可走。数值关系直接写进关卡数据：狐狸 `blocks: 1` → 两窟就够；猎人 + 狐狸 `blocks: 2` → 必须三窟。这就是"三窟"的出处，不是文案讲的。
- 单测：1 窟遇 `blocks 1` → 不安全；2 窟遇 `blocks 1` → 安全；3 窟遇 `blocks 2` → 安全；2 窟遇 `blocks 2` → 不安全；没挖通的洞不算退路；反复点同一个洞不增加退路；autoplay 不卡死。

### 2.3 `split` —— 换了个分法，绳上还是那七颗

```ts
export const SplitLevelSchema = z.object({
  total: z.number().int().min(2).max(12),        // 一共几颗：那条守恒的线
  bins: z.array(SplitBinSchema).length(2),       // 两个盘子：id / kind / x / y / label
  /** 观众只看其中一个盘子：够这个数就高兴（照原文：朝三暮四则怒，朝四暮三则悦） */
  audience: z.object({
    watchedBinId: z.string().min(1),
    happyAt: z.number().int().positive(),
    happyLine: z.string().min(1),
    angryLine: z.string().min(1),
  }),
  hint: z.string().min(1).max(24),
})
.refine((l) => l.audience.happyAt <= l.total, {
  message: '高兴的门槛比总数还大，观众永远不会高兴', path: ['audience', 'happyAt'],
})
.refine((l) => l.bins.some((b) => b.id === l.audience.watchedBinId), {
  message: '观众看的那个盘子不存在', path: ['audience', 'watchedBinId'],
});
```

- 判定：`moveOne(state, from, to)`（挪一颗）、`mood(watchedCount, rule)`（只看被注视的那一个盘子）、`conserved(state, total)`（恒真，但值得断言）。**模板只判观众的反应，不判对错**："骗"不"骗"由叙事去说，代码不说教。
- 单测：怎么挪总数都不变；3/4 → 怒、4/3 → 喜；7/0 也"喜"，但另一侧为 0（模板只报事实，不评价）；边界（0 颗 / 全在一侧）；`happyAt > total` 被 schema 挡住；autoplay 不卡死。

### 2.5 庖丁为什么用专属场景

`butcher` 的核心是"顺着缝把一块骨头推出去"，是一次性机制（推块 → 滑开 → 刀口无损）。塞进 `trace` 会把它"只看顺序、不看手感"的语义拧变形；塞进 `place` 又丢掉了方向。按盘古 `chaos`、烽火 `beacon` 的先例做成游戏专属场景，关卡数据仍用 `butcher` schema 登记在模板层 —— 双语校验、schema 体检照旧覆盖。

### 3.1 刻舟求剑（`kezhou`，模板：`mark`，一屏）

- **故事两幕**：① 楚国有个人坐船过江，船到江心，他的剑"噗通"一声掉进了水里；② 他在船帮上刻了一个记号："我的剑就是从这儿掉下去的。" 船靠了岸，他从刻记号的地方跳下去找 —— 剑呢？
- **keyMoment**（beatId s2）："船一直在走，剑一直在原来的地方 —— 记号刻在哪儿才找得到剑？" → 刻在船上没有用，因为船在走（canonical）；揭晓语："剑掉下去的地方不会动，船会动。"
- **玩法**（一屏，约 60–90 秒；**整条江都在一屏里，不滚动**）：
  1. **掉剑**：剑从船上滑落 → 水花 → 沉到左边的水底（**一直看得见**：水底一点微光，位置从头到尾不动）。这是整个典故的视觉论证，所以剑绝不能离开画面。
  2. **刻记号**：三个地方都能刻 —— **船帮**（会漂走）、**下游岸边的石头**（不动，但位置不对）、**落剑处岸边的树**（不动，位置也对）。点一下、划一道都行，宽容度给足。
  3. **开船**：船从落剑处漂到岸边（约 4 秒；水在流、船在动、船帮上的刻痕**跟着船一起走** —— 孩子的眼睛能直接看见"记号在动"）。
  4. **下水**：从刻记号的地方跳下去捞 → 只摸到水草和气泡 → 旁白："记号跟着船走了。"（零惩罚，船自动回到上游，可以再刻一次）
  5. **再来**：这次刻在树上 / 丢一个浮标 → 船照样漂走，树和浮标一动不动 → 从树下的水面下去 → **摸到剑**。
- **结局**：剑出水、抖一抖水珠；船帮上那道刻痕还在（给一个特写）→ 语音："船走了，水在流，剑还在原来的地方。记号要刻在不动的地方。"
- **教学点**：世界在变，办法也得跟着变；**不嘲笑那个楚人** —— 原文只说他"惑"（糊涂），孩子自己撞一次就懂了。
- **迁移题提案**：放学回家的路，你是记住"从学校门口直走，第二个路口右转"，还是"跟着前面那辆车走"？→ 跟着车走不行：车会拐弯（记号要落在不动的东西上）✓

### 3.2 狡兔三窟（`jiaotu`，模板：`burrow`，一屏）

- **故事两幕**：① 草地上，一只兔子在吃草，天上有一只鹰在盘旋；② 冯谖对孟尝君说："狡兔有三窟，才免于一死。你只有一个窟，还不能高枕无忧 —— 请让我再给你凿两个。"
- **keyMoment**（beatId s2）："一个洞，够不够？" → 要多凿几个，才睡得安稳（canonical）。
- **玩法**（一屏草地剖面，约 60–90 秒；**没有倒计时、没有追赶**）：
  - 草地上有三处可以凿的土坡（左 / 中 / 右），点一下挖一铲，三铲凿通一个窟；兔子钻进去探一下头（表示"这个洞能用了"）。
  - **第一次危险**（狐狸，`blocks: 1`）：狐狸径直蹲到一个洞口。这时：
    - 只有 1 窟 → 兔子出不来（**不出现抓咬**：兔子在洞里缩着，旁白只陈述"只有一个洞，狐狸一守，它就出不去"；狐狸蹲一会儿就走了）
    - 已有 2 窟 → 兔子从另一个洞口溜出来吃草，旁白"洞多一个，退路就多一条"
  - **第二次危险**（猎人 + 狐狸，`blocks: 2`）：两处洞口被守住，只有三窟才躲得过 → 孩子把第三个窟凿通 → 兔子从最远的那个洞口探出头。
  - 孩子可以只凿一个就想往下走 —— **允许**：这正是"自己撞一次"。凿窟不花资源、不扣分、可以反复。
- **结局**：三个洞口成品字形，兔子在洞里睡得四脚朝天，天上那只鹰还在盘旋，但够不着 → 语音（原文）："狡兔有三窟，仅得免其死耳。三窟已就，君姑高枕而乐矣。"
- **教学点**：**多留一条退路**；顺带交代一句"这是冯谖对孟尝君说的"（figures 里有冯谖、孟尝君）。
- **迁移题提案**：明天要出远门，天气预报说下午可能下雨 —— 带一把伞，还是"到时候再说"？✓

### 3.3 百步穿杨（`yangyouji`，模板：`aim` + `ladder`，一屏）

- **故事两幕**：① 楚国有个叫养由基的人，射箭很准。他把一片柳叶挂在树上，退到一百步以外；② 一箭出去，正中柳叶；再一箭，又中。围观的人几千个，都喊"好箭法"。
- **keyMoment**（beatId s1）："一百步以外的一片柳叶，怎么射得中？" → 一箭一箭练出来的（canonical）；揭晓语："百发百中，不是天生的。"
- **玩法**（一屏白天的柳林靶场，约 60–90 秒）：
  - 拉弓的手势与后羿一致（按住瞄准 → 松手射箭），但**这里是"自己往后退"**：地上立着木牌，写着十步 / 三十步 / 五十步 / 八十步 / 百步，点一下木牌就往后退一档，画面拉远、柳叶变小（**距离和大小同时变**，孩子一眼看得见代价）。
  - 每一档命中一次即晋级：箭钉在柳叶上，叶子上留下一个圆孔（穿过去的表现）；射偏了叶子晃一晃，箭插在树干上或地上 —— **不重来、不扣分**，接着射。
  - 五档全中 → 木牌从"十步"一路亮到"百步"。
  - 最后一档给一点点光晕提示（这是给 7–10 岁的，不是硬核射击），保证射得中。
- **结局**：百步之外一箭穿叶、钉在树上，箭尾还在抖；树下围观的人群剪影举起手 → 语音："百发百中，是一箭一箭练出来的。"
- **与后羿的区分（必须做足）**：后羿 = 夜空、十个大太阳、射九留一（主题是**分寸**）；百步 = 白天柳林、一片越来越小的柳叶、越练越远（主题是**练**）。画面、目标、节奏三重区分 —— 验收第 5 条专门查这一对。
- **尺度**：只射柳叶，不射任何活物。
- **迁移题提案**：第一次跳绳跳不过去 —— 是绳子不好，还是练得不够？✓

### 3.4 朝三暮四（`zhaosanmusi`，模板：`split`，一屏）

- **故事两幕**：① 宋国有个养猴子的人（狙公），家里的橡子不够了，得省着喂；② 他跟猴子们商量："早上给你们三颗，晚上给四颗。" 猴子们全都跳起来生气。他改口："那就早上四颗、晚上三颗。" 猴子们全都高兴地趴下了。
- **keyMoment**（beatId s2）："早上三颗晚上四颗，和早上四颗晚上三颗 —— 有什么不一样？" → 总数都是七颗，一颗也没多（canonical）。
- **玩法**（一屏，约 60–90 秒）：
  - 画面中间是一条绷直的草绳，**七颗橡子串在上面**；绳的左半边是"早上"的竹盘，右半边是"晚上"的竹盘，中间一块可以拖动的分界木牌。
  - **拖动分界木牌**左右移动 = 换一种分法（也可以点单颗橡子左右拨，两种都收）。开局就是原文的 3 + 4。
  - 树下的猴子（5 只剪影）**只看早上那一盘**：早上的数 ≥ 4 就欢呼，≤ 3 就炸毛跳脚 —— 规则照原文，写在数据里（`audience.happyAt = 4`）。
  - **守恒的可视化是这一部的全部**：不管是 3+4、4+3 还是 7+0，绳上一直是七颗；挪动的时候能看见橡子在绳上滑过去，没有人加、没有人减。
  - 走通：把 3+4 改成 4+3 → 猴子破涕为笑 → 停 2 秒 → 揭破："早上四颗、晚上三颗 —— 和刚才一样，都是七颗。" 猴子还是那几只猴子，橡子还是那七颗。
  - 自由试：孩子可以试 7+0（猴子更高兴，但画面转到夜里，猴子饿得睡不着；旁白只陈述"它们早上高兴，晚上饿"，**不评价**）。
- **结局**：猴群安静下来，镜头拉开：树上那七颗橡子一颗没多、一颗没少；旁边灰色的虚影显示刚才的 3+4，两个画面叠在一起 → 语音："说法换了一个，橡子一颗也没多。"
- **教学点**：名义变了，实质没变；也提醒孩子**别被说法牵着走**（原文"名实未亏而喜怒为用"）。
- **迁移题提案**：妈妈说"先写作业再看动画片"，你说"先看动画片再写作业" —— 两件事都要做完，换了个顺序，作业会变少吗？✓

### 3.5 庖丁解牛（`paoding`，专属场景 `butcher`，一屏）

- **故事两幕**：① 庖丁给文惠君解牛：手一碰、肩一靠、脚一踩、膝盖一顶，骨肉就"哗"地分开，刀锋的声音像音乐；② 文惠君说："你的刀怎么这么好？" 庖丁说："我这把刀用了十九年、解过几千头牛，刀口还像刚从磨石上磨出来的 —— 我顺着骨节之间的缝走刀，从不硬砍。"
- **keyMoment**（beatId s2）："十九年、几千头牛，刀为什么还像新的一样？" → 顺着骨缝走刀，不硬砍（canonical）。
- **玩法**（一屏牛身拼图，约 60–90 秒，**三段递进**）：
  1. **所见无非牛者**：一整头牛，孩子随便点一下 / 划一刀 → "当"一声，刀被骨头弹回来，**刀口上多一个缺口**（刀口小图 +1；不失败、不倒扣、随时可以接着来）→ 旁白（原文）："始臣之解牛之时，所见无非牛者。"
  2. **未尝见全牛也**：牛身上的**缝隙亮起来**（骨节之间的纹路像地图一样发光）。把刀放进一条缝，**顺着缝的方向把那一块推出去**（拖动方向与缝一致即可，容差给足）→ "咔"地一声，那块骨肉滑开。一块一块，把整头牛顺着缝拆开。
  3. **以神遇而不以目视**：最后两块**不给提示**，孩子凭刚才记住的结构自己推 —— 推对了，刀口上一个缺口都没有。
  - 画面右下角一直有一把刀的小图：刀刃上的缺口一个一个加上去（唯一一种"记分"，而且只加不减）。
- **结局**：整头牛变成一张**完整的骨架**摊在灯下（每一块都是顺着缝分开的，没有一处是砍断的），庖丁把刀擦干净挂起来 → 语音（原文）："以无厚入有间，恢恢乎其于游刃必有余地矣。" 再加一句白话："十九年，刀刃还像新磨的一样。"
- **尺度**：牛是**圆润卡通的骨块拼图**（6–8 块），**无血、无内脏、无死亡**，孩子看到的是一张会滑开的拼图。
- **迁移题提案**：鞋带打死结了 —— 使劲拽，还是先看看结是怎么打的、找到那一根一抽就开？✓
