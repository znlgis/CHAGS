# 三十六计小游戏 · 总体方案（待确认）

> 目标：**一计一个游戏，36 个**。分组 `stratagem` 已经在 [groups.ts](../packages/content/src/groups.ts) 里占好位置
> （见《技术方案》§7.8），这份方案说的是怎么把 36 个真实的内容与玩法填进去。
>
> 本文档**只是方案**，不含实现。确认后按第六节的批次执行，每批单独验收。

---

## 一、结论先说

1. **36 个游戏 ≠ 36 份 JSON。** 现有典故组 17 个游戏背后是 12 个可复用玩法模板；
   三十六计要做的是"**每计一个专属动词**"，因此新增 **14 个模板**、复用现有 3 个模板
   （`wait` / `split` / `trace`），36 计各占一个。
2. **规模是现有典故组的 2.5 倍左右**（约 3.5–4 万行，含双语内容与测试）。
   所以分 **6 批 × 6 计**交付，按传统"六套"切分，每批是可玩、可验收的里程碑。
3. **最大的风险不是技术，是尺度**：三十六计里有借刀杀人、笑里藏刀、美人计、苦肉计。
   方案给出一套**儿童化原则**（第三节）：计名与原文保留，冲突抽象成"难题 / 赛场 / 棋盘"，
   教的是"动脑子"，不是"骗人"；防御性的几计落在**识别**而不是**使用**上。
4. 每批结束跑 `pnpm verify` + `pnpm e2e` 全绿，与现有 17 部典故同一个门槛。

## 三、儿童化原则（六条硬规矩）

面向 6–12 岁，与现有 17 部典故同一套底线：

1. **计名与原文保留**——这是要认识的文化内容；但"解语"重写成孩子能懂的一句话，
   每计再给一条**正向迁移句**（"这一计今天可以怎么用"，见上表最后一列）。
2. **冲突抽象化**：不写"敌"字，换成"难处 / 对手 / 局面"；场景优先选渡口、棋盘、赛场、集市、工地、山林、书斋。
3. **三不出现**：不出现死亡与流血；不出现欺压弱者；**不出现"骗朋友"**——所有计策只对"难处/对手"用。
4. **防御性的几计只教"识别"**：笑里藏刀（看穿）、反间计（自己看到才信）、
   美人计（了解对方在意什么）、苦肉计（信任要从真代价来）——
   玩法落在"看穿 / 了解 / 判断"，**不落在这招怎么使**。
5. **零惩罚**：失败只是重来，不扣星、不卡进度（沿用现有做法）。
6. **每计一个"思维标签"**：如 借力 / 留退路 / 看清时机 / 先试再动 / 舍小保大——
   图鉴上显示，家长一眼看得懂孩子在学什么。

## 四、模板策略：复用 3 + 新增 14

现有模板库 12 个（substitution / tap / place / aim / sort / trace / wait / mark / split / burrow / butcher / beacon）。
三十六计里能**诚实地**复用的只有 3 个（9 隔岸观火、34 苦肉计、36 走为上）——
其余 33 计需要新的循环与判定，这就是这一批的本体工作量。

| 新模板 | 一句话机制 | 覆盖的计 | 模式 |
|---|---|---|---|
| `ruse` 示形 | 我做我的，你看到的是我想让你看到的 | 1、6 | hide（藏形过检）/ divert（引开视线） |
| `twoline` 双线 | 明面维持"看起来在动"，暗线推进真进度 | 8、33 | stack（修栈道）/ plant（让他自己看到） |
| `swap` 替换 | 在两次清点之间把关键件换掉，外形要瞒过检查 | 21、25 | shell（替身）/ beam（换梁） |
| `show` 造势 | 用有限的资源营造"看起来很大"的规模 | 7、29 | draw（画出来）/ borrow（借现成的势） |
| `stillness` 忍 | 最难的动作是**不动**：忍住、屏息、等第二通鼓 | 4、27、32 | bide（等第三鼓）/ feign（装糊涂）/ calm（屏息） |
| `window` 时机窗口 | 窗口只开一小会儿，早了晚了都白费 | 5、12、20 | fire（等他乱）/ glimpse（顺路抓）/ stir（自己搅浑） |
| `probe` 试探 | 敲一下、看一眼，用**反应**获取信息 | 13、18、26 | knock（打草）/ spot（找王）/ hint（旁敲） |
| `lure` 诱饵 | 放对饵，让他离开、让他上钩、让他动心 | 15、17、31 | decoy（诱离）/ trade（以小引大）/ favor（投其所好） |
| `matchup` 配对编排 | 手里这些牌，怎么配对、按什么顺序出 | 11、23 | pair（田忌赛马）/ order（远交近攻） |
| `chain` 连环 | 前一步必须为后一步创造条件 | 24、30、35 | pass（借道）/ step（逐步接管）/ domino（连环） |
| `siege` 要害 | 打要害、断退路、抽支撑、收梯子 | 2、19、22、28 | vital / support / close / ladder |
| `borrow` 借力 | 力不一定要自己出 | 3、14 | force（借力源）/ banner（借名号） |
| `chase` 追而不逼 | 追上很容易，难的是**保持距离** | 16 | — （单模式） |
| `read` 识破 | 从有限线索里判断他真正的打算 | 10 | — （单模式） |

**内部只做两套骨架，登记成 14 个模板**：`timekit`（时间轴 + 判定窗口，供 stillness / window / chase 用）
与 `stagekit`（"外表 vs 真相"的物体与检查者，供 ruse / twoline / swap / show / borrow 用）。
这样 14 个模板不等于 14 份重复代码。

**与现有模板一样，每个模板必须实现 `runAutoplay()`** —— 现有 17 部典故的 e2e 就是靠
`?autoplay=1` 一条用例走完全程的（见 `packages/phaser-kit/src/baseScene.ts`、各模板 `*.ts`）。
新模板不实现 autoplay，就等于没有端到端验证。

## 七、数据模型改动（建议在批 1 之前先做，一次到位）

《技术方案》§7.8 已经预告过：**等三十六计真有游戏了，再连同 `kind` 做一次"内容条目"改名**。
现在就是那个时候——越晚改，要改的地方越多。

1. **改名**：`allusions/` → `entries/`；`AllusionContent` → `ContentEntry`；
   `getAllusion` / `allusionsFor` / `allusionsByYear` → `getEntry` / `entriesFor` / `entriesByYear`。
   ⚠️ **存档字段名不动**：`SaveData.allusions` 里的键是内容 id，字段名再改就得写迁移，
   而玩家已有的星星不能"消失"。这一条作为硬约束写进测试。
2. **`kind` 加第五个值 `strategy`（兵法）**：游戏馆徽章、图鉴分组用。
3. **新增 `stratagem` 字段**（仅三十六计有，且**必须有**）：
   ```ts
   stratagem: {
     number: 1..36,      // 计策序号，同时也是它在组内的排列位置
     set: 1..6,          // 第几套（胜战/敌战/攻战/混战/并战/败战），套名是 i18n 文案
   }
   // 按语原文写在 source 里：book = 《三十六计·胜战计》，quote = 按语节选。
   // 战例史源（《史记·…》《左传·…》）写在故事分幕与 figures / era 里 ——
   // 逐字确证不了的史源原文，宁可用计策按语，也不编造引文。
   ```
   校验（构建期，`content:check` + `groups.test.ts`）：
   - `group === 'stratagem'` ⟺ 有 `stratagem` 字段；典故组不许有；
   - **登记顺序必须等于计策序号**（组内排序 `orderBy: 'index'`，顺序错了大厅就乱）；
   - 序号 1–36 不重不漏；第 n 套 = 序号 6(n−1)+1 … 6n；
   - `set` 名称中英各一份，放在 `packages/i18n/src/messages.ts`（`stratagem.set.1..6`），不重复写 36 遍。
4. **e2e 分组用例要改**：现在 `smoke.spec.ts` 断言"三十六计组 0 个入口 + 敬请期待"，
   批 1 上线后必然失败 —— 改成与典故组同样的"数量取自内容目录"。
5. **空组文案**：`group.stratagem.empty` 从"第一批计策正在赶工"改成 36 计齐了之后的说法（批 6 收尾）。

## 十、风险与对策

| 风险 | 对策 |
|---|---|
| **儿童尺度**（借刀杀人 / 美人计 / 苦肉计 / 笑里藏刀） | 第三节六条硬规矩；每批方案里**逐计**给出改写与迁移句，交你过目后再写代码 |
| 史源不准 | 每计给出处（书名 + 篇名 + 原文节选）；演义与存疑明确标注，沿用"后世学者多存疑"的既有做法 |
| 规模大、易半途而废 | 6 批 × 6 计，每批独立可玩可验收；批 1 之后手感不对，随时可以调整后面 5 批的模板策略 |
| 模板太多（14 个） | 内部只做 `timekit` / `stagekit` 两套骨架，登记成 14 个模板；批 5、6 不再新增模板 |
| 体积预算 | 36 个 chunk 都是懒加载；`assets` 预算（3500 KB）大概率要上调 —— 先实测，再在 `check-size.mjs` 里改并写明原因 |
| e2e 时长 | 36 条 autoplay 用例 ≈ +2–4 分钟；必要时按套分片（`--shard`），不删用例 |
| 改名波及 17 部典故 | 批 0 单独做：只动名字与目录，不动逻辑；`pnpm verify` + `e2e` 全绿后再加内容；存档字段名不动 |
| 玩家存档 | 内容 id 不变、存档字段名不变，旧存档继续可读；这条写进测试 |
