# 打包与分发：便携 EXE 与安卓 APK

> 目标：**Windows 上一个 exe 双击就跑，不装**；**安卓一个 apk 装上就玩**。
> 同一份站点产物（`apps/site/dist`）喂给两个壳，游戏代码零改动。

---

## 0. 一条命令

```bash
pnpm dist:win    # → apps/desktop/src-tauri/target/release/chags.exe      （约 3.3 MB）
pnpm dist:apk    # → apps/mobile/android/app/build/outputs/apk/release/app-release.apk
```

两个脚本都会先构建站点产物，再交给各自的壳。

---

## 1. 目录结构

```
apps/site/                     Vue 应用（唯一的产品代码）
apps/desktop/                  Tauri 桌面壳
  src-tauri/tauri.conf.json    窗口尺寸、图标、frontendDist 指向 site/dist
  src-tauri/src/main.rs        20 行的壳
apps/mobile/                   Capacitor 安卓壳
  capacitor.config.ts          webDir 指向 site/dist
  android/                     安卓工程（入库，便于复现）
  resources/                   图标与启动图源文件
scripts/make-icons.py          用 Pillow 几何绘制生成图标
```

---

## 2. 为什么是这个技术组合

| | 选型 | 理由 |
|---|---|---|
| Windows | **Tauri 2** | 用系统自带的 WebView2，产物 **3.3 MB**；Electron 同样功能要 150 MB |
| 安卓 | **Capacitor 8** | Web 套壳的行业标准；内置本地服务（`https://localhost`），ES module / IndexedDB / WebGL 全部按浏览器标准工作 |
| 语音 | **原生 TTS** | **Android WebView 没有实现 Web Speech API**，只靠 `speechSynthesis` 安卓版会全程没旁白 |

> Electron 还有个坑：我们的 `index.html` 用 `<script type="module" crossorigin>`，
> 在 `file://` 下会被 Chromium 的 CORS 拒绝，必须额外注册自定义协议。
> Tauri 默认就走自定义协议，这个坑不存在。

## 3. 平台适配层（架构早就留好了）

`packages/platform/src/runtime.ts` 做运行环境探测，**不 import 任何壳的 SDK**：

```ts
detectRuntime(): 'web' | 'tauri' | 'capacitor'
nativeTextToSpeech()   // 通过 window.Capacitor.Plugins 取原生 TTS
nativeApp()            // 安卓返回键
```

好处：Web 包体积零增长，浏览器里也不会有插件报错。

### 语音怎么选

```ts
speak(text, locale) {
  ① 原生 TTS（安卓）→ 安卓系统语音引擎
  ② Web Speech API（桌面 WebView2 / 浏览器）
  ③ 都没有 → 静默降级，只保留音效，绝不报错卡住
}
```

### 安卓返回键

在游戏或图鉴里按返回 → 回到典故馆；已经在典故馆 → 才退出应用。
不处理的话，孩子在游戏里误按返回键会直接把应用关掉。

### 竖屏与全屏

- `AndroidManifest.xml`：`android:screenOrientation="portrait"`
- `styles.xml`：`windowFullscreen` + `windowLayoutInDisplayCutoutMode=shortEdges`（刘海屏）
- CSS：`#app` 用 `env(safe-area-inset-*)` 让开刘海与手势条

## 4. 签名与安全

| 文件 | 是否入库 | 说明 |
|---|---|---|
| `apps/mobile/android/keystore.properties` | ❌ | 本地签名配置 |
| `*.keystore` | ❌ | **务必自己备份**；丢了就只能让用户先卸载再装新版 |
| `apps/mobile/android/local.properties` | ❌ | 本机 SDK 路径 |

没有 keystore 时，Gradle 会**自动退回 debug 签名** —— 产物依然可以安装，方便别人自己构建。

### 首次构建需要

1. **JDK 17–21**（JDK 25 可能超出 Gradle 8.14 的支持范围）
2. **Android SDK**：`platforms;android-36` + `build-tools;36.0.0`（Capacitor 8 要求 compileSdk 36）
3. **Rust 工具链** + **MSVC C++ 生成工具**（Tauri）
4. **WebView2 运行时**（Win10/11 通常已内置）

## 5. 分发

- **Windows**：直接发 `chags.exe`，双击即用，不需要安装、不写注册表。
  未签名的 exe 首次运行会有 SmartScreen 提示（"更多信息 → 仍要运行"）。
  要消掉它需要代码签名证书（约 ¥1000–3000/年）。
- **安卓**：直接发 apk，用户需要在设置里允许"安装未知来源的应用"。
  上 Google Play 需要 AAB + 隐私政策，且**儿童类应用受 Families 政策约束**，成本高得多。

**建议**：先直接分发文件，跑通体验再考虑上架。

---

## 6. 打包没有改变的东西

- 游戏代码一行没改：两个壳都只是加载同一份 `apps/site/dist`
- 存档仍然是 IndexedDB，在桌面与安卓上都能持久保存
- 中英切换、`?lang=`、`?autoplay=1` 在两端都照常工作
- `pnpm verify` 与端到端测试完全不受影响（它们针对的是 Web 产物）
