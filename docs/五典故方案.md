## 0. 先说最大的风险

这五个典故里，**女娲补天是"修补"，后羿射日是"精准"，剩下三个——夸父、精卫、愚公——内核都是"坚持"**。
如果偷懒让三个都用"连点涨进度"，做出来就是同一个游戏换皮，孩子玩到第三个就腻了。

方案的做法：**同一个模板，三种完全不同的手感与节奏**（见 2.2），并且每个典故都必须有一个
**只属于它的"签名画面"**——那才是孩子记住的东西。

| 典故 | 动作 | 签名画面（记忆锚点） |
|---|---|---|
| 女娲补天 | **补** | 五色石嵌进天上的窟窿，霞光洒下来 |
| 后羿射日 | **射** | 九个太阳坠落，最后一个温暖地挂着 |
| 精卫填海 | **填** | 小鸟衔着一块小石头，投向无边的大海 |
| 夸父追日 | **追** | 他倒下后，手杖化成一片桃林 |
| 愚公移山 | **移** | 门前的大山没了，远处露出通往汉阴的路 |

## 2. 模板策略：1 次泛化 + 1 个新模板 + 1 个复用

### 2.1 为什么先泛化 `grow`

现在的 `grow` 模板把"撑开天地"的画面写死在里面了，只能给盘古用。
但它真正的价值是**连点推进的循环**：计数、进度曲线、阻力、连击、音调反馈、卡住提示、自动通关。

**做法：把画面完全交出去，模板只留循环。**

```ts
// 泛化后：tap 模板
export interface TapConfig {
  level: TapLevel;              // targetValue / stepValue / unit / resistance / hint / mode
  session: SessionState;
  nextSceneKey: string;
  /** 进度 0..1，画面完全由游戏决定 —— 这是四个典故"不像同一个游戏"的关键 */
  drawStage: (g: Phaser.GameObjects.Graphics, progress: number, stage: StageMetrics) => void;
  /** 可选：里程碑（愚公的三代交接、智叟出现） */
  milestones?: { at: number; id: string }[];
  onMilestone?: (id: string, done: () => void) => void;
}
```

- `mode: 'tap'` → 连点（盘古撑天、精卫投石、愚公挖山）
- `mode: 'hold'` → 长按（夸父奔跑：松手就慢下来，有紧张感）

盘古现有的撑天视觉**下沉到 `games/pangu/src/scenes/hold.ts`**，由它实现 `drawStage`。
这是纯搬迁，有 e2e 兜底。

### 2.2 三个"坚持"类典故怎么做出差异

| | 输入 | 一轮的节奏 | 画面变化 | 额外机制 |
|---|---|---|---|---|
| **盘古** | 连点（快） | 一下一丈，密集 | 天升地降，人被拉长 | 音调随高度上升 |
| **精卫** | 连点（慢） | 点一下 → 小鸟飞过去 → 投下 → 飞回来 | **海面上一座小岛慢慢长大** | 小鸟与大船的体量对比 |
| **愚公** | 连点 + 交接 | 挖到一定量 → 人变老 → 点"交给下一代" | 山一点点变小，门前渐渐透光 | **三代人接力**；智叟出现质疑 |
| **夸父** | **长按** | 按住就跑，松手就慢 | 太阳沿弧线前进，夸父在后面追 | 追到河渭可以喝水 |

同一套进度逻辑，四种节奏与画面 —— 这是方案里最花心思的地方。

### 2.3 新增 `aim` 模板（拉弓瞄准）

```ts
export interface AimConfig {
  level: AimLevel;              // targets / hitRadius / arrowSpeed / goalCount
  session: SessionState;
  nextSceneKey: string;
  drawTarget: (g, kind: string, x: number, y: number, alive: boolean) => void;
  drawArcher: (g, x: number, y: number, pull: number) => void;
  /** 关键：射够数量后必须停手 */
  onAllButOneShot?: () => void;
}
```

可复用典故：**纪昌学射、百步穿杨、惊弓之鸟**（都是"精准"类）。

### 2.4 女娲补天直接复用 `place`

`place`（拖东西到该去的地方）已经跑通在两处（盘古化身）。女娲补天是同一个动作：
把石头拖到天上破的洞里。

**关键：用"形状"而不是"颜色"作为匹配依据**（五色石刚好有五种颜色，但只靠颜色会让色弱的孩子吃亏，
这也违反我们自己定的无障碍规则）。颜色做装饰，形状做判定。

## 3. 五个游戏逐个设计

### 3.1 女娲补天（place 复用，最省）

- **开场**：两幕故事 → 天塌下来（不周山倒下的剪影）
- **玩法**：天上破了 **5 个洞**（对应五色石），拖石头补上去
  - 拿起来时，对得上的洞会发光（沿用 place 的零失败设计）
  - 补好一个洞，天空亮一分
- **结束画面**：五个洞都补好 → 五色霞光洒下 → 干裂的大地回暖
- **签名画面**：五色石嵌进窟窿的瞬间
- 资源：5 种石头形状（圆/方/三角/菱形/星形）× 5 种颜色

### 3.2 后羿射日（aim 新模板，最有戏剧性）

- **开场**：十日并出，庄稼枯焦
- **玩法**：从弓的位置向外拖 → 显示轨迹 → 松手射箭
  - 拖得越远，箭越快
  - 射中太阳 → 太阳爆开、坠落
- **★ 关键抉择（本游戏的教学核心）**：
  射下 9 个之后，**最后一个太阳会变得温暖、大地开始返绿**。
  如果玩家把它也射下来 → **天一下子黑了**（1.5 秒）→ 太阳自己回来 →
  屏幕上一句短提示"要留一个太阳"。**零惩罚，让他自己撞一次就懂了。**
- **结束画面**：九个太阳坠落，最后一个温暖地挂着，焦黄的大地变绿
- **签名画面**：射九留一

### 3.3 精卫填海（tap 泛化）

- **开场**：两幕故事 → 女娃落水化作精卫
- **玩法**：点一下 → 精卫叼起石头飞向海面 → 投下 → 飞回；连点加快
- **画面**：海面上浮起一座小岛，一点点变大；精卫很小，海很大
- **结束画面**：海上出现一小片陆地 → 精卫还在飞（循环感）
  → 旁白："她一直填到今天。"
- **签名画面**：小鸟与大得不成比例的海

### 3.4 夸父追日（tap 泛化，hold 模式）

- **开场**：两幕故事 → 夸父决定去追太阳
- **玩法**：**长按奔跑**；松手就慢下来，太阳越跑越远
  - 追到河渭时，可以点一下喝水（短暂加速）
- **画面**：太阳沿弧线前进，夸父在后面追，背景从平原到河渭到大泽
- **结束画面**（温柔处理，**不表现死亡**）：
  夸父跑不动了，慢慢坐下 → 手杖落在地上 → **桃林一朵朵绽开**，花瓣飞起来
- **签名画面**：桃林

### 3.5 愚公移山（tap 泛化 + 里程碑）

- **开场**：两幕故事 → 愚公一家面山而居，出门要绕很远
- **玩法**：点击挖山；每挖到约 1/3：
  - **智叟出现**，摇头嘲笑，站在山前挡路 → 玩家继续点（挖山）→ 智叟的表情从嘲笑变成惊讶 → 默默走开
  - **换代**：愚公变老 → 出现"交给下一代"的按钮 → 点一下，儿子接棒（人物变小一号），山继续变小
- **画面**：山一点点变小，门前渐渐透出远处的路
- **结束画面**：天帝感动，夸娥氏二子把两座山背走 → 门前豁然开朗，一条大路通向远方
- **签名画面**：子子孙孙接力
